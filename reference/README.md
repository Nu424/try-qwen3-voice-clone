# reference/ — 参照音声の置き場所

クローンしたい声の音声と、その書き起こしをここに置きます。

**このディレクトリの中身は `.gitignore` で除外されています**（このREADMEを除く）。
個人の声や第三者の素材が意図せず公開されないようにするためです。

## 用意するファイル

| ファイル名 | 内容 |
|---|---|
| `reference_audio.wav` | クローンしたい声の音声 |
| `reference_text.txt` | その音声の書き起こし（UTF-8、改行なしの1行でよい） |

別のファイル名を使う場合は、生成時に `--ref-audio` / `--ref-text` で指定できます。

## 音声の条件

前処理スクリプトがモノラル・24kHz に変換するので、**形式は何でも構いません**
（ffmpeg が読めれば mp3, m4a などでも可）。重要なのは中身です。

| 条件 | 理由 |
|---|---|
| **話者が1人だけ** | 話者エンコーダは音声全体から1つの特徴ベクトルを作るため、複数話者が混ざると平均化され、誰にも似ない声になる |
| **ノイズ・BGMが少ない** | ノイズも「その話者の声の特徴」として取り込まれ、生成音声に乗る |
| **3〜15秒**（公式推奨） | 短いと特徴を捉えられず、長いとプロンプトが伸びて遅くなる |

## 書き起こしは音声と正確に一致させる

**ここが品質を最も左右します。**

モデルは「このテキストを読むとこの音声になる」という対応を例示として受け取り、
そこから声だけを取り出して別のテキストに適用します。
書き起こしがズレていると、この対応関係が壊れて品質が落ちます。

そのため、**音声を短く切るなら、書き起こしも対応する範囲に手で合わせてください。**
書き起こしが全長に対応しているなら、推奨の15秒を超えていても
切らずに全長を使う方が良い結果になります（30秒程度なら実測で問題ありません）。

## 置いたあとの前処理

```bash
.venv/Scripts/python.exe scripts/prepare_reference.py
```

`reference_24k_mono.wav` が作られ、生成時にはこれが使われます。

長さを切る場合:

```bash
.venv/Scripts/python.exe scripts/prepare_reference.py --start 0 --duration 12
```

文の切れ目は無音検出で探せます（閾値は素材に応じて調整してください）:

```bash
ffmpeg -v info -i reference/reference_audio.wav -af silencedetect=noise=-40dB:d=0.12 -f null -
```
